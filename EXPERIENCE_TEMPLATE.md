## 3. Work-item worksheet

### Work item A

- Situation or problem: What needed attention?

- Output: Dashboard, analysis, workflow, recommendation, release, report or operating result.
- Current result: What exists or changed? If no verified impact metric exists, describe the completed work instead.
- Evidence: Public link, project file, report, release, dashboard, meeting record or person who can verify it.

## 4. Convert each item into a résumé bullet

Use this compact pattern:

> **Action verb + specific work + scope/context + method + verified output/result.**

Examples with no invented performance claim:

- Analysed sales, traffic, fees and product performance across eight European Amazon markets using [tools], producing [recurring output] for [decision or stakeholder].
- Developed an HTTP-to-WebSocket telemetry flow with time-series storage and a React dashboard, enabling a simulated flight to be monitored through live status and trajectory views.
- Structured five research alternatives in an adjustable MCDA interface, making criterion weights and ranking changes visible for team review.

If a result is not measurable, finish with the real deliverable or decision supported. Do not add a percentage, revenue number, time saving or user count unless the evidence field supports it.

## 5. Website version

The website can use slightly more context than the résumé:

- **Overview:** 1–2 sentences on the role purpose and scope.
- **Selected work:** 3–5 concise bullets from the worksheet.
- **Tools:** Only tools actually used in this role.
- **Outputs / evidence:** Named deliverables and public links where available.
- **Related case:** Project title and case-study URL, when the work maps directly to a published project.

Do not publish empty evidence links, internal customer information, credentials or confidential metrics.

## 6. Evidence strength

- **A — Public:** live product, repository, published report or public case study.
- **B — Shareable on request:** non-public but safe portfolio sample or redacted document.
- **C — Internally verifiable:** work record, dashboard, release or manager/colleague confirmation.
- **D — Accurate description only:** the work is real but no result evidence is currently available; describe the activity and output without an impact claim.

## 7. Final check

- Does each bullet begin with a precise action?
- Is your own contribution distinguishable from the team’s work?
- Is the scope concrete where evidence exists?
- Does each metric have a source?
- Is the most relevant work first for the target role?
- Are current roles in present tense and completed roles in past tense?
- Can a reader understand every bullet without internal jargon?
